ТЕКУЩЕЕ СОСТОЯНИЕ
-----------------
- Ядро загружается через Limine (x86_64, higher-half).
- Прерывания стабильны: PIC, TSS/IST (Double Fault устранён).
- Вывод: VGA 0xB8000 + Serial COM1 + Framebuffer (vesa.rs, шрифт 8x16).
- Интерактивный shell: команды help/echo/about/tasks/clear/cursor/
  test_alloc/test_pmm/test_paging/test_process/run_user.
- Аллокатор кучи: 8 МБ (linked_list_allocator).
- PMM: bitmap 128 KB, alloc_frame/dealloc_frame.
- Пейджинг: map_page/unmap_page/translate, create_user_p4, map_page_in_p4.
- Процессы: create_process, enter_ring3 (IRETQ → ring 3).
- Syscall: int 0x80 (DPL=3), syscall_handler, возврат в kernel mode.

ЗАДАЧИ НА СЛЕДУЮЩУЮ ИТЕРАЦИЮ (по приоритету)
------------------------------------------

1. ЧТЕНИЕ РЕГИСТРОВ В SYSCALL (главная задача)
   - InterruptStackFrame не содержит GPR (rax, rdi, rsi...).
   - Нужна asm-обёртка: сохраняет регистры на стек, вызывает Rust-обработчик.
   - Тогда: eax = номер syscall, rdi/rsi/rdx = аргументы.

2. SYSCALL WRITE/EXIT
   - write(fd, buf, len) — вывод строки из user space (копирование через HHDM)
   - exit(code) — завершение процесса, возврат в shell

3. ELF-ЗАГРУЗЧИК
   - Парсинг ELF64 header
   - Загрузка сегментов в адресное пространство процесса
   - Передача управления на entry point

4. (ЕСЛИ ОСТАНЕТСЯ ВРЕМЯ) МНОГОПРОЦЕССНОСТЬ
   - Список процессов, планировщик round-robin
   - Переключение контекста (сохранение/восстановление регистров)

ПРАВИЛА (.kodaruls)
------------------
1. Одна операция в один момент времени.
2. Никогда не переписываем файл — точечные исправления.
3. Всегда проверяем зависимый код.
4. Никогда не применяем исправления без объяснения.
5. Логировать в my_kernel.log (только дописывать).
6. Новый код — бирюзовым цветом (до коммита).
7. Объяснять рациональность предложений.
